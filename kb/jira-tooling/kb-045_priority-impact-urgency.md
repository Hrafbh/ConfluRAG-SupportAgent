## Summary
Règles simples pour proposer une priorité cohérente (sans jargon technique).

## Définitions
- **Impact** : combien de personnes/process sont touchés.
- **Urgence** : combien le temps compte (activité en cours, cut-off, opérations terrain).
- **Priorité** : combinaison des deux (ce que l’équipe traite en premier).

## Grille simplifiée
- **P1** : indisponibilité globale OU opérations terrain bloquées (pas de workaround).
- **P2** : dégradation importante OU module clé partiellement KO (workaround possible).
- **P3** : problème isolé, non bloquant, demande d’info, amélioration.

## Exemples RoutePilot
- P1 : login KO pour plusieurs sites pendant les tournées.
- P2 : exports lents/KO mais usage possible autrement.
- P3 : question “comment faire”, correction d’un rôle, problème sur 1 utilisateur.

## Verification
La priorité proposée est justifiée dans le ticket (impact + urgence).
