## Summary
Page “source” qui liste les incidents/problèmes connus pour éviter de réinvestiguer à chaque fois.

## Format recommandé (par item)
- **Titre** : symptôme court
- **Impact** : qui est touché
- **Workaround** : contournement
- **Statut** : en cours / mitigé / résolu
- **Dernière mise à jour** : date
- **Lien** : ticket interne / page runbook / note release

## Process
1) Ajouter un item quand un problème se répète.
2) Mettre à jour quand workaround ou fix est disponible.
3) Fermer/archiver quand résolu depuis un délai raisonnable.

## Verification
Les agents support consultent cette page avant d’escalader.
